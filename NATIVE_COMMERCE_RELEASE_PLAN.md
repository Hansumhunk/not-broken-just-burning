## Technical critical path (not deployed)
1. Finished founder-approved versioned assets, checksum, filename, size, accessibility, price/tax/refund approval. Upload only to a new private product bucket, with no browser write/list access. Keep private material out of public GitHub entirely.
2. Add protected product registry (slug, active version, approved Stripe price ID, currency, amounts, private storage key; draft/off state), and transaction ledger (order UUID, user FK, product slug, price ID, checkout session ID unique, payment intent unique, state, paid/refunded amounts, timestamps). RLS on all exposed tables, service-only writes, own-order reads only when needed; no reflection content. Resolve duplicate active purchase atomically (single pending order per user+slug plus expiry; idempotent Stripe session creation keyed by order ID; do not create another while pending; recheck ownership). No live DB change in this branch.
3. Separate create-product-checkout endpoint, authenticated via verified JWT, server-owned price lookup and readiness gate (disabled by default), account from token, quantity 1, Stripe mode=payment, client_reference_id/order metadata assigned only by backend, fixed-origin success/cancel URLs; explicit approved tax behavior. Refuse unavailable assets, unapproved price, duplicate or existing active ownership. No client-supplied price/amount/identity. Do not modify existing subscription checkout.
4. Separate signed product webhook endpoint; verify raw Stripe signature and expected environment; re-fetch Checkout Session and line items from provider, reconcile order, user, exact price, currency, quantity, payment status, payment intent. Never grant based solely on redirect or event metadata. Handle paid completion and async success; unpaid, failed, canceled/expired do not grant. Handle refunds/disputes via authoritative intent/charge lookup, monotonic reconciliation and approved policy; partial refunds require explicit rule. Atomic order/entitlement upsert in one transaction using server role, unique session/payment identifiers; retries and concurrency must not grant twice or resurrect revoked access. Subscription events ignored by commerce handler and subscription handler remains unchanged. Dedicated event receipt or mutually exclusive handler routing.
5. Product download endpoint checks verified current user against active/unexpired entitlement on every request, resolves only server registry storage path, issues short-lived signed URL (e.g. 60 seconds); no listing, no public asset URL. Downloaded local copy cannot be recalled; access policy must acknowledge this. Return no protected URL on failure. Library re-access independent of membership cancellation. Success page says checking until confirmed, not "owned" until authoritative entitlement exists. Support missing access without asking for card details.
6. Implement production-independent sandbox QA, CI, founder browser test and approval; enable only approved SKUs after secure storage and delivery verified. No automatic deployment from draft.
