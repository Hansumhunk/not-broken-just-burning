## Staff reconciliation workflow
The Deno tool `launch-backend-staging/commerce/admin-cli.ts` refuses production ref/live keys. It is not a web admin interface. Use from controlled QA operator terminal with limited QA service key and Stripe test key; never in browser, public logs, or repo. Environment: same QA URL/ref/mode/key as worker, service role key, NBJB_COMMERCE_OPERATOR set to approved alias. No card numbers or personal details. Always run read-only first; --apply needs --operation and --ticket UUIDs (controlled case record, not personal details), plus operator alias. Command prefix: `deno run --allow-env --allow-net launch-backend-staging/commerce/admin-cli.ts`.
| Command | Effect / guard |
| --- | --- |
| inspect ORDER_UUID | Bounded provider session scan, sanitized counts and payment/refund/dispute verification. No writes. Scan cap 2000; ambiguity fails closed. |
| review ORDER_UUID --apply --ticket UUID --operation UUID | Audits and flags order for reconciliation; records duplicate suspicion if multiple paid sessions. |
| recover ORDER_UUID --apply ... | Re-fetch provider session, exact line/price/intent/charge, successful refunds; repair failed/missing grant. Reject competing orders, stale snapshot, pending refunds, revoked same-order rights, account holds and full refund. |
| restore ORDER_UUID --apply ... | Only locally disputed order and provider disputes ALL won, with remaining paid funds; audited restore. Active/lost/warning disputes stay held. |
| close-refund ORDER_UUID --apply ... | Close a provider-confirmed full refund (including late paid/expired exception); matching entitlement only, no money movement. |
| erasure-check USER_UUID | Counts active rights/open orders/disputes/review and retained records; never authorizes deletion. |
| erasure-hold USER_UUID --apply ... / erasure-cancel USER_UUID --apply ... | Audited freeze/unfreeze of new checkout reservations after verified support request. |
| replace-asset SKU --old-version V --old-key PATH --new-version V --new-key PATH --name FILE --apply ... | Verify new private file exists; record one immutable SKU/version-specific correction mapping; preserve old purchase snapshot. New orders reference registry's version. No overwrite. |
If stale snapshot or unique conflict occurs, re-run inspect. If multiple Stripe sessions or multiple paid orders, stop grants and refunds; inspect each provider payment in sandbox Dashboard, record reference in restricted support case, verify which canonical payment is valid and manually refund duplicates only after approval. Current worker does not auto-refund or merge duplicate provider charges. More than one matching Stripe session remains a manual review blocker; design a reviewed multi-payment reconciliation before live launch. No customer ID/payment ref in executive exports.

A one-hop replacement mapping is supported for one original asset; a subsequent correction requires reviewed mapping extension, not overwriting private storage. Current script does not delete old assets.
