# Resource Tools V2 — Preparation Only

This branch is a workshop. Nothing here should be released merely because it is drafted.

## Shared product rule

Each NBJB resource should teach just enough, let the client do the work, produce a useful result, and keep sensitive reflection private by default. Device-local persistence must be explicit and clearable. Generated language should remain a draft the client can revise, not a verdict.

## Flame Check-In V2

- Optional device-local draft restore.
- Build a concise check-in summary: body signal, emotion, thought, boundary, need, next action.
- Add Copy / Clear with accidental-clear protection.
- Route high-risk crisis language to Support & Safety without attempting diagnosis.
- Offer one relevant next resource based on the client-selected need, using transparent rules rather than hidden scoring.

## Pattern Map V2

- Device-local autosave.
- Separate observation, repetition, exception, interpretation, possible explanation, and unknowns visually.
- Add a pattern-discipline summary that explicitly says repetition can justify investigation but does not automatically prove motive or cause.
- Add Six Sacred Questions handoff when context is incomplete.
- Copy / Clear with local-storage disclosure.

## Boundary Builder V2

- Guided fields: behavior, impact, need/value, boundary, action I control, consequence/action if repeated, wording I can actually say.
- Detect wording that tries to control another person's feelings or behavior and prompt the client to rewrite it as an action they control.
- Generate an editable boundary statement from the client's own entries.
- Add a distinction between boundary, request, threat, punishment, and wall.
- Device-local autosave, Copy, Clear, accidental-clear protection.

## One Stone V2

- Guided fields: mountain/problem, what must happen eventually, what matters today, smallest next action, estimated effort, obstacle, support/resource needed.
- Generate a single 'next stone' card rather than a giant plan.
- Optional three-stone queue, but never gamify distress with streaks or shame.
- Device-local autosave, Copy, Clear.
- Route back to Flame Check-In if the client cannot identify a workable action because they are overloaded.

## Six Sacred Questions V2

- Preserve the six writable Who / What / When / Where / Why / How boxes.
- Optional device-local draft persistence.
- Build organized notes from all six answers.
- Add a transparent completeness review: distinguish unanswered context from conclusions.
- Do not score truth, credibility, guilt, motive, or legal merit.

## Cross-tool continuity

A future Member Hub may store low-sensitivity routing state such as 'last tool used' or current Path focus. It must not silently upload the contents of Forge notes, Pattern Maps, Sacred Six worksheets, medical/legal material, or other sensitive reflections.

Potential handoffs:

Flame Check-In → Forge / Boundary Builder / One Stone
Forge → Pattern Map / Six Sacred Questions / One Stone
Pattern Map → Six Sacred Questions / Forge
Boundary Builder → Guardian Path / One Stone
Six Sacred Questions → Forge / Pattern Map
One Stone → Member Hub / Path focus

## Release gate

Before any V2 tool reaches main: desktop and mobile behavior QA, blank/long input tests, refresh/restore test if localStorage is used, Copy/Clear tests, keyboard testing, reduced-motion check, privacy copy update, validator pass, and explicit review that the tool does not imply diagnosis, legal truth, motive detection, or independent fact verification.
