## Approved execution candidate — NOT TO RUN NOW
Use documented supported DROP (RESTRICT, never CASCADE) and CREATE with schema extensions in SQL editor, only after confirming managed ownership permissions and exact version. Prefer a single transaction where supported; abort before commit if prerequisites or verification fail. Confirm no active writers inside maintenance window immediately before executing. Never flip extrelocatable in system catalogs. Official reference: https://supabase.com/docs/guides/database/extensions/pg_net#troubleshooting. Treat dropping as destructive even when the queue is empty. If managed provider requires an alternate procedure, follow Support guidance. Do not change default privileges or event trigger by speculation.

## Validation / restoration
Verify extension namespace extensions, expected version, net objects/signatures and managed event trigger, ACL baseline, worker healthy via supported diagnostic, queue empty, Data API net excluded and known application dependencies intact. Run a harmless controlled QA endpoint request only after approval; verify request/response, no credentials in returned payload, and existing workflow smoke tests. Preserve archived responses separately rather than injecting them into a live queue; only restore response history with a vendor-supported approach that preserves IDs and does not send requests. Rerun security advisor; relocation alone does not eliminate managed net ACLs. If no longer needed, consider disabling only after dependency review and explicit approval.
## Rollback and stop criteria
If any preflight differs, stop; if transactional DDL fails, rollback before commit; if post-commit error, keep producers paused, do not repeatedly drop/recreate. Review health/logs; restore previous supported extension version and public registration using the same documented drop/recreate process only with approval, then verify objects, sequence strategy, managed grants, consumer tests, and no duplicate outbound requests. Restore retained historical response archive only through reviewed supported process or keep separately for audit. Resume producers gradually after owner signoff, recheck counts, advisors, HTTP schema visibility, and monitor existing Weekly Operations Review. Any response restoration/backup gap is a no-go. Source state is not a full production backup.
